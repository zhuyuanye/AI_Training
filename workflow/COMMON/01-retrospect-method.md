# 复用示例 01｜复盘成功做法

静态分享请看[本步骤的输入输出产物示例](../examples/COMMON/01-retrospect-method.md)；本次不需要现场执行。

这是主流程之外的可选示例。适合在 BA 完成一次真实的需求提取、澄清和人工纠正后演示。

## 使用模式

**Plan**。先提炼经过实践的方法，不立即生成或安装 Skill、Command。

## 输入

- 已完成实践记录：`{{已完成实践记录}}`，例如本轮 BA 的需求依据表、问题清单及处理过程。
- 人工纠正及最终采用结果：`{{人工纠正记录}}`。
- 本次要复用的范围：会议转写 → 候选需求 → 最多三个优先澄清问题。
- 产物目录：`{{产物目录}}`。

## 输出

- 触发条件、输入、步骤、输出模板和检查规则。
- 可复用方法与一次性业务答案的区分。
- 切换 Build 后归档到 `{{产物目录}}/reuse/method-review.md`。

## 可复制提示词（Plan）

```text
请复盘一次已经完成并实际检查过的 BA 工作，不要开始处理新需求。
实践记录：{{已完成实践记录}}
人工纠正与最终采用结果：{{人工纠正记录}}

仅提炼“从会议转写提取候选需求并提出优先澄清问题”的可复用方法：
1. 哪些输入和步骤帮助我们得到可靠结果，哪些最初做法被人工纠正；
2. 何时应使用这套方法，何时不适用；
3. 如何引用来源，区分决策、建议、推断、冲突和待确认；
4. 如何结合现有系统判断本次变化，并优先提出最多三个关键问题；
5. 输出模板、完成条件，以及规则未知或资料缺失时如何处理。

每条方法注明它来自哪段实际实践或哪次人工纠正。未经验证的建议单独列出，不当成成功经验。
排除本次会议的人名、账号、客户信息、金额阈值和一次性业务结论，不把它们写成通用规则。
给出适合沉淀到 Skill 的方法和适合放到 Command 的入口参数，避免在两处重复维护全部指令。
本轮只在对话中输出方法候选稿，不写文件、不生成 Skill／Command；如果没有真实实践记录，先说明缺少哪些材料，不编造“已经验证”。
```

## 保存结果（切换 Build）

```text
请把上一轮复盘中已经核对的方法和人工修正保存到 {{产物目录}}/reuse/method-review.md。
保留每条方法的实践依据、适用范围、输入输出、未验证建议及明确排除的一次性业务答案。
只写这份复盘文档，不创建或调用 Skill、Command。没有实际确认的候选方法仍标候选。
```

## 人工检查与下一步

检查沉淀的是有效工作方法，且没有把本次业务答案变成默认规则。进入[生成 Skill 与 Command](02-create-skill-command.md)。
