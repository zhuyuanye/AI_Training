# 复用示例 03｜新会话换材料验证

静态分享请看[本步骤的输入输出产物示例](../examples/COMMON/03-verify-reuse.md)；本次不需要现场执行。

验证方法是否已保存到可复用文件，以及它能否处理不同输入。成功不能只依靠上一轮会话记忆。

## 使用模式

**Build**。在目标项目中新建 OpenCode 会话，调用上一步指定了 `agent: build` 的 Command；它将实际生成本轮候选文档。

## 输入

- 目标项目：`{{目标项目目录}}`，已包含上一例的 Skill 和 Command。
- 另一份原始材料：`{{新材料路径}}`，不要复制上一轮业务答案。
- 全新的输出目录：`{{新产物目录}}`。
- 人工对照后的反馈：`{{复用验证反馈}}`，在实际执行后填写。

## 输出

- 新材料的候选需求、来源依据、优先澄清问题。
- `{{新产物目录}}/reuse-validation.md`，记录加载、执行与人工核查结果。
- 如果方法有缺陷，记录需修订位置，不自动声称复用通过。

## 执行步骤

1. 在目标项目中打开一个新 OpenCode 会话，不带入上一轮完整业务对话。
2. 先确认 Command 可以找到。若找不到，检查上一例的文件与目标项目位置，再按本机 OpenCode 的实际行为重新加载会话；不要声称创建文件就必定即时生效。
3. 替换路径后调用：

```text
/meeting-discover "{{新材料路径}}" "{{新产物目录}}"
```

4. 检查 Agent 的工具或执行记录是否实际加载了 `meeting-discovery`。只有输出看起来类似，不能证明 Skill 被调用。
5. 现场核对新材料中的来源与歧义，再复制下面的检查提示词。

## 可复制提示词（Build，复用检查）

```text
请核验刚才 /meeting-discover 的真实执行，不重新生成一份看起来正确的结果。
本轮新材料：{{新材料路径}}
本轮产物目录：{{新产物目录}}
人工核对反馈：{{复用验证反馈}}

检查：
1. Command 是否在目标项目真实可用，是否有实际加载 meeting-discovery Skill 的记录；
2. 是否读取了本轮新材料，并在本轮输出目录生成实际文件；
3. 候选需求是否引用真实来源，是否区分事实、建议、推断和未决项；
4. 是否沿用了上一轮的人名、业务阈值或结论等不应固化的答案；
5. 是否正确处理新材料中的缺失或冲突，并优先提出最多三个有业务影响的问题；
6. 是否仅执行候选需求与澄清范围，没有擅自生成正式 AC 或下游业务实现。

将实际核验结果、人工反馈、证据位置和待修订项写入 {{新产物目录}}/reuse-validation.md。
没有加载或执行证据的项标未证实。区分命令可调用、技能已加载、产物已生成和方法符合要求，不能混成一个“成功”。
只写验证记录，不修改原始材料、Skill 或 Command；需要修订时指出具体规则，再回上一例做小范围调整。
```

## 人工检查与下一步

如果发现一次性业务答案被固化，回到[复盘方法](01-retrospect-method.md)；如果路径、格式或 Command 调用有问题，回到[生成资产](02-create-skill-command.md)。修订后再换一份输入或复现已发现的问题。
