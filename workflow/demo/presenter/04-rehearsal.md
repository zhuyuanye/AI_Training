# 分享准备｜只检查展示材料

本次不做现场真实执行，因此不需要准备业务仓库、账号、数据库、Java／Node 环境或 OpenCode 会话。

## 课前准备

1. 选择 [60 或 90 分钟顺序](01-runbook.md)，按表预开所需文件。
2. 打开 [示例总索引](../../examples/README.md)，确认 BA／DEV／TEST 每步都能进入原提示词和样例。
3. 把 Markdown 字号放大；长表重点展示两三行，完整表作为课后材料。
4. 直接打开 [HTML 原型](../../examples/prototype/index.html)。它是本地静态页面，无网络或服务依赖，三种状态同时可见。
5. 检查 PPT 中三张流程图的编号与 12 步文件对应。
6. 将初始业务输入与后续答案分别打开；先展示问题，再切到预设产品回复。
7. 准备两个重点：DEV 的 if 漏洞；TEST 的 15 通过／1 阻塞是模拟结论。
8. 自建 Skill／Command 只展示 Markdown 内的样例，避免误说成已经安装或运行成功。

## 自己讲一遍时核对

- 能否从 REQ 回到会议时间戳？
- 能否从 TC-05 回到 AC-01/04/06，再回到产品 DEC？
- 是否解释了 Plan 分析与 Build 保存／修改／运行的区别？
- 是否把 DEV 的 review 遗漏讲成反例，而非推荐做法？
- 是否清楚说出日志与 XML 只是示意，Trace／截图并不存在？
- 是否说明课后真实使用要重新取证，不能套用样例结果？

## 不需要做的准备

不为了这个静态案例创建真实用户、修改应用、生成“看似真实”的测试截图，也不把示例路径包装成项目路径。
