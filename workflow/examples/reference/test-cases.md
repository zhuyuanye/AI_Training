# test/test-cases.md｜完整测试设计样例

版本：TC-v1。依据：[AC-v1](ac.md)。**预期结果来自业务决策，不来自代码。没有实际执行。**
示例 API 与用户标识见 [CODE-v1](code-context.md)，真实使用时替换为项目已核实的协议和动态测试数据。

所有写操作用独立临时数据；负例比对操作前后快照，不能只检查错误码。每条案例独立准备和清理，避免某条成功修改污染其他测试。

|---|---|---|---|---|
| TC-01 | 管理员，唯一新用户名；请求不含 email | 新增 API | 拒绝、邮箱错误、不新增记录 | API；01/05/06 |
| TC-02 | 管理员，新用户 email=null | 新增 API | 拒绝且无新增 | API；01/06 |
| TC-03 | 管理员，新用户 email="" | 新增 API | 拒绝且无新增 | API；01/06 |

| TC-15 | 个人资料、导入、注册与通知的原行为对照材料 | 对照调用链与变更，并核对代表操作 | 本次管理端规则未影响这些入口；记录核对范围 | 人工＋静态；08 |
| TC-16 | 完整旧格式与唯一性规则集尚未提供 | 待补规则集后回归 | 各旧规则行为保持；目前不得填通过 | 待定，阻塞；09 |

API 项数按 12 个顶层案例统计；TC-10 内有新增和编辑两个动作，不另算两个顶层用例。UI 1 项、人工 2 项、阻塞 1 项，合计 16。真实框架参数化时需重新按实际报告口径统计。
