# shared/decisions.md｜共同决策样例

案例：REQ-DEMO-EMAIL-001。版本：DEC-v1。状态：**教学设定中假定已由产品确认；现实中没有发生该确认。**

依据：[产品澄清卡](../../demo/presenter/02-product-clarification-cards.md)。产品回复不是原会议里已经确定的答案。

| DEC | 教学口径 | 来源 | 关联 |
|---|---|---|---|
| DEC-01 | 本轮只覆盖管理端新增、编辑及承接它们的保存接口，直接请求也必须校验 | P01、P09 | REQ-01、REQ-02、Q-01 |
| DEC-02 | 不传、null、空串、仅普通空格／制表符／换行，均不能满足必填 | P02 | REQ-01、Q-02 |
| DEC-03 | 去首尾空白后校验并保存；不删除内部字符，不主动改大小写、既有格式或唯一性策略 | P03、P05 | REQ-01、Q-02 |
| DEC-04 | 不批量回填、不停用历史账号；查询和登录不变；管理端编辑保存必须补邮箱，即使改其他字段 | P04 | REQ-03、Q-03 |
| DEC-05 | 页面必填提示“请输入邮箱”；接口可识别邮箱问题，返回结构和状态沿用项目约定 | P06 | REQ-04、Q-04 |
| DEC-06 | 校验失败不创建新用户，不部分更新旧资料；允许纠正后重试 | P07 | REQ-04、Q-05 |
| DEC-07 | 权限和其他字段规则不变；不新增通知、验证邮件或新角色 | P08 | REQ-05、Q-06 |
| DEC-08 | 个人资料、导入、注册、手机号必填不纳入本轮；共享校验的波及必须检查 | P01、P09 | REQ-05、Q-01 |

仍待核验：完整既有邮箱格式和唯一性规则、真实 API 错误约定、源码位置。产品确定“沿用”不代表 Agent 已经知道沿用的具体内容。

教学中将局部代码／接口约定设为 [CODE-v1](code-context.md) 以继续展示；完整旧规则回归保留为 BLOCK-01，不用样例替真实项目补证据。
