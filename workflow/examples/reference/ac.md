# shared/ac.md｜三方共用的验收标准样例

案例：REQ-DEMO-EMAIL-001。版本：AC-v1。依据：[DEC-v1](decisions.md)。
状态：**教学设定的共同评审稿，假定产品确认 AC-01—08；AC-09 待补旧规则明细。不是实际签字记录。**

| AC | Given／When／Then，可观察的业务结果 | 追溯 | 状态 |
|---|---|---|---|
| AC-01 | 有维护权限的管理员新增用户或保存编辑；邮箱不传、null、空串或仅约定空白时；页面阻止保存，直接请求同一保存接口也被拒绝 | REQ-01/02，DEC-01/02 | 教学已确认 |
| AC-02 | 管理员填写首尾有约定空白的有效邮箱；保存；先清理首尾再校验，保存值与清理后的值一致 | REQ-01，DEC-03 | 教学已确认 |
| AC-03 | 邮箱内部有空格等字符；保存；不能删除内部字符拼成另一地址，应按既有格式规则判断 | REQ-01，DEC-03 | 教学已确认；格式全量见 AC-09 |
| AC-04 | 历史用户邮箱为空；仅查询或登录仍可按原规则使用；管理员编辑并保存任何字段时必须补邮箱，保存前有清楚提醒 | REQ-03，DEC-04 | 教学已确认 |
| AC-05 | 邮箱必填不满足；页面提示“请输入邮箱”；API 返回可识别邮箱问题的失败，不重定义项目技术返回约定 | REQ-04，DEC-05 | 教学已确认 |
| AC-06 | 新增或编辑因邮箱无效被拒；校验前后业务数据不变；用户纠正后可重试并成功保存 | REQ-04，DEC-06 | 教学已确认 |
| AC-07 | 无维护权限者尝试新增或编辑；维持原拒绝规则；有权限者的其他字段校验也保持不变 | REQ-05，DEC-07 | 教学已确认 |
| AC-08 | 本次部署后，个人资料、导入、注册等范围外入口及通知逻辑保持原行为；不因复用校验产生额外必填要求 | REQ-05，DEC-08 | 教学已确认 |
| AC-09 | 对双方核对过的旧邮箱格式与唯一性规则集逐项回归；除本轮必填和清理行为外结果不变 | REQ-01/05，DEC-03/07 | 待补规则集，BLOCK-01 |

边界：AC 定义期望，不能根据后端当前是否实现而删改。AC-09 的规则集缺失阻塞该项验收；AC-01—08 可用于演示设计，但不能由此宣称整体可发布。
