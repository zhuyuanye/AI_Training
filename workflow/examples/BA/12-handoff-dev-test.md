# BA 12｜交接 DEV 与 TEST：输入输出示例

[对应提示词](../../BA/12-handoff-dev-test.md) · 实际工作模式：**Build**

> 合成教学样例，用于静态讲解；不是已执行记录或真实产品确认。

## 输入示例

输入 BASELINE-v1 与当前范围、BLOCK-01。
交接目标：DEV 可以定位实现；TEST 可以继续设计，不需要重新猜会议意思。

## 输出产物示例

### ba/handoff.md

交付：US-01 新增补齐邮箱；US-02 历史编辑补齐邮箱；共同口径见 BASELINE-v1。
DEV 优先核查：页面→API→校验→写入链路；编辑省略 email 是否仍校验；共用校验是否波及范围外入口。
TEST 输入：原始分析、DEC-v1、AC-v1；依据业务设计，不从当前代码反推期望。
关键风险：页面拦截掩盖 API 绕过、历史用户编辑受限、失败部分写入、范围外波及。
待补：BLOCK-01；不得把完整旧格式／唯一性回归写为通过。
交接确认（教学设定）：开发接收有限范围进行分析，测试接收设计输入；未发生真实发布批准。

若产品改变历史编辑政策，回到 DEC-04 和 AC-04，并更新所有受影响产物。

## 讲解检查点

交接应给出输入入口、范围与待办；不是把整个聊天记录交给下一个角色。
