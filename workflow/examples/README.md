## 每个文件怎么看

每一步都包含：原提示词链接、实际工作中使用的模式、本步骤输入片段、对应输出文件的内容样例、讲解检查点。**Plan 的文件样例是对话结果归档后的形态；实际保存时使用原步骤中的 Build 归档提示词。** 本次展示这些预先整理的文档即可。

文内 `ba/…`、`dev/…`、`test/…`、`shared/…` 是假设工作实例的产物位置，不代表培训目录下存在同名运行文件。样例保存在本目录，并链接到可查看的内容。

输入按时间推进：BA 01—04、TEST 01—02 保留问题；后续步骤才引用产品口径、AC 和实现。首次向学员展示原始需求时，不同时展开后面的答案。

## 案例中的版本与结果

- `DEMO-BASE`：虚构修改前版本，邮箱可空。
- `DEMO-CHANGE-A`：虚构首次交付，新增必填和编辑显式空串校验已经加入，但编辑请求省略邮箱时漏校验。
- `DEMO-FIX-B`：虚构修复版本，编辑保存无论是否传邮箱都进入必填校验。
- 上述是教学标签，**不是 Git 提交号**；没有真正的应用仓库或这些版本。
- 模拟首轮：API 12 项，10 通过、1 失败、1 环境错误；UI 1 通过；人工 2 通过；另有 1 项完整旧格式／唯一性回归阻塞。
- 模拟复测：API 12 通过、UI 1 通过、人工 2 通过；旧规则完整回归仍有 1 项阻塞。故模拟结论也不能写成“全部通过，可以上线”。
- 以上统计用于讲解，**实际执行数为 0，真实项目的质量状态未知**。
