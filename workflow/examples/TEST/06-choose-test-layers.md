## 输出产物示例

### test/test-strategy.md

| 层次 | 选择 | 理由 |
|---|---|---|
| API | TC-01—12，共 12 个顶层案例 | 绕过页面直接测规则、权限及保存后的数据 |
| UI | TC-13，共 1 个核心流程 | 历史用户编辑→提示→纠正→成功并重新打开 |
| 人工 | TC-14、15，共 2 项 | 文案／入口与范围外行为需要解释和对照；包括静态核对 |
| 待补 | TC-16，共 1 项阻塞 | 缺完整旧规则，不能靠多写脚本填补 |

每条 API 单独准备数据与清理；失败也要比对快照。
UI 不重复全部邮箱数据组合；业务矩阵由 API 承担，页面验证可用性与连接是否正确。
TC-15 明确代表操作和静态检查范围，不把“代码未改”直接等同全部回归通过。
进入自动化前：确认协议、框架、测试身份、数据隔离和证据位置。
