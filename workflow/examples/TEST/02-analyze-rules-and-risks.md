# TEST 02｜分析规则、歧义与风险：输入输出示例

[对应提示词](../../TEST/02-analyze-rules-and-risks.md) · 实际工作模式：**Plan**

> 静态教学样例；业务确认、实现、脚本与结果均为示意，未执行真实测试。

## 输入示例

输入 TEST 01 的业务材料，不读取代码。
业务原句片段：“改善邮箱资料完整性；尽量不影响老用户使用；填错时应知道怎么改。”

## 输出产物示例

### test/requirement-analysis.md

| 业务线索 | 可提出的测试关注 | 不能自行确定的规则 |
|---|---|---|
| 邮箱资料完整 | 不传、null、空串、纯空白、有效值 | 空白字符与清理范围 |
| 不影响老用户 | 登录查询、编辑其他字段、原数据 | 编辑保存是否强制补邮箱 |
| 有用的提示 | 页面提示、接口错误可识别、重试 | 固定文案与技术错误码 |
| 既有系统调整 | 权限、其他入口、失败数据一致性 | 哪些入口属于本轮 |

风险排序：绕过页面直接保存；历史用户操作被误阻；失败部分写入；共享校验扩大范围。

### test/questions.md

TQ-01：哪些入口和调用方式受约束？关联候选范围风险。
TQ-02：不传／空值／空白、首尾和内部字符分别怎样处理？
TQ-03：历史空邮箱用户继续使用和编辑保存有什么区别？
后续队列：TQ-04 错误反馈；TQ-05 失败数据；TQ-06 权限与旧规则。

以上都是问题／风险，不是已确认 AC。

## 讲解检查点

按业务反例思考，比提前给测试一套 AC 再让它扩写更能发现遗漏。
